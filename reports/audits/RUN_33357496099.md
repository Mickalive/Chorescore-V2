## Findings

### 1. MUSTFIX — Share sheet natif non fonctionnel sur Android

- **Path** : `src/infrastructure/local/LocalSystemShareAdapter.ts`
- **Problème** : l'adaptateur SystemShareGateway repose uniquement sur l'API Web Share (`navigator.share`), inexistante dans React Native/Hermes sur Android. Sur l'APK réel, `isAvailable()` renvoie toujours false et `share()` toujours `{completed:false}` → alerte « Partage indisponible ». Le livrable central de V2-05 (« share sheet natif depuis ≥2 contextes ») n'est pas atteint sur le produit réel.
- **Preuve** : `isAvailable()` = `typeof navigator !== 'undefined' && !!navigator.share` ; aucune dépendance native de partage dans `package.json` ; ScoreScreen et AddTaskScreen routent via `app.shareContent` ; le test n'affirme que `typeof result === 'boolean'` (tautologique).
- **Réparation requise** : implémenter l'adaptateur avec le share sheet natif (`Share.share` de react-native ou expo-sharing), conserver un `isAvailable()` honnête, ajouter un test de délégation à l'API native.
- **Vérification** : sur l'APK Android, « Partager » dans Score et dans une entrée d'historique ouvre le share sheet système.

### 2. MUSTFIX — ShareCard visuelle = code mort

- **Path** : `src/ui/components/ShareCard.tsx`
- **Problème** : le composant n'est rendu dans aucun écran ; seul `generateShareText` est utilisé. Le partage est en texte seul, alors que l'acceptance exige des « Share cards ChoreScore générées et partageables » (visuelles, lisibles sur mobile).
- **Preuve** : grep — ShareCard importé uniquement dans `index.ts` et le test ; aucun mécanisme de capture d'image ni option `files` dans le gateway.
- **Réparation requise** : rendre la ShareCard dans le flux de partage et la partager comme image/fichier via SystemShareGateway (`files`), ou supprimer le composant mort.
- **Vérification** : le partage depuis Score/historique produit une carte visuelle partageable via le share sheet natif.

### 3. MUSTFIX — Galerie de captures reproductibles absente

- **Path** : `reports/audits/TRUSTED_33357496099.md` (et dépôt)
- **Problème** : requiredEvidence de V2-05 inclut `visual-evidence` ; QG-4 exige une galerie reproductible à partir de V2-05 ; DESIGN_BRIEF liste 12 écrans. Aucune capture n'existe.
- **Preuve** : aucun PNG/JPG/WebP hors ressources Android ; la sortie trusted ne contient que tests/export/prebuild/gradle.
- **Réparation requise** : produire la galerie (connexion, racine foyers, Ajouter Premium, Ajouter Free + archive, Score Premium, Score Free, To-do Premium, mini-formulaire, To-do Free, upsell historique, Options, share card, états vides/erreurs) comme artefacts reproductibles.
- **Vérification** : artefacts présents et reproductibles depuis l'arbre accepté.

### 4. MUSTFIX — Contraste WCAG AA en échec

- **Path** : `src/ui/design-system/theme.ts`
- **Problème** : `textSecondary` #81B29A et `textMuted` #A8A8B3 (légendes, dates, infos secondaires, placeholders, badges, boutons désactivés) échouent AA sur toutes les surfaces ; `warning`/surface 2.97 ; `primary`/background 4.47. Le test d'accessibilité ne vérifie que les paires `colors.text` (sombre).
- **Preuve** : ratios calculés — textSecondary/background 2.27, /surface 2.40, /surfaceAlt 2.15, /surfaceHighlight 2.03 ; textMuted/background 2.24, /surface 2.36, /surfaceAlt 2.11, /surfaceHighlight 1.99 ; warning/surface 2.97 ; primary/background 4.47.
- **Réparation requise** : assombrir `textSecondary`/`textMuted` (et ajuster `warning`/`primary`) pour ≥4.5:1 sur toutes les surfaces ; étendre le test de contraste à toutes les paires réellement utilisées.
- **Vérification** : contrôle automatisé de contraste sur toutes les paires utilisées passe WCAG AA.

### 5. MUSTFIX — Faux push présenté comme actif

- **Path** : `app/options/personal.tsx`
- **Problème** : « Notifications push: Activées », « Rappels de tâches: Activés », « Nouvelles assignations: Activées » affichés alors que `LocalNotificationAdapter.isAvailable()` = false. Violation de l'acceptance V2-05 (« pas de faux push ») et de QG-1.
- **Preuve** : lignes 76-78 et 101 : valeurs codées en dur ; l'adaptateur est honnête mais l'UI ne reflète jamais l'indisponibilité.
- **Réparation requise** : états honnêtes (« Non configuré » / « Indisponible ») ou branchement sur la disponibilité réelle.
- **Vérification** : Options affiche des états de notification cohérents avec l'adaptateur.
