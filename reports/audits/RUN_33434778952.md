## Finding 2 — logConflict/getConflictLog household-scoped

**Status: FIXED**

`src/infrastructure/local/LocalSyncAdapter.ts` (lines 136-146):
```ts
logConflict(householdId: string, resolution: ConflictResolution): void {
  const log = this.conflictLog.get(householdId) ?? [];
  log.push(resolution);
  this.conflictLog.set(householdId, log);
}
getConflictLog(householdId: string): ConflictResolution[] {
  return [...(this.conflictLog.get(householdId) ?? [])];
}
```
`logConflict` now takes an explicit `householdId` and stores under that key (the bogus `entityId.split('-')[0]` derivation is removed). `getConflictLog(householdId)` returns only that household's conflicts. A two-household isolation test (`should isolate conflict logs between two households`) verifies household A sees only its own conflict, household B only its own, and an unknown household returns empty.

## Finding 3 — getPendingInvitations resolves userId→email with exact matching

**Status: FIXED**

`src/application/use-cases/ChoreScoreApp.ts` (lines 771-776):
```ts
async getPendingInvitations(userId: string): Promise<Invitation[]> {
  if (!this.services.invitations) return [];
  const user = await this.repositories.users.getById(userId);
  if (!user) return [];
  return this.services.invitations.getPendingInvitations(user.email);
}
```
The app resolves the user's email via the user repository before passing it to the adapter. `src/infrastructure/local/LocalInvitationAdapter.ts` (lines 83-87) uses exact matching:
```ts
getPendingInvitations(email: string): Promise<Invitation[]> {
  return Array.from(this.invitations.values()).filter(
    inv => inv.status === 'pending' && inv.invitedEmail === email
  );
}
```
The substring `includes` matching is removed. Tests verify userId→email resolution (`should get pending invitations via userId (resolves to email)`) and no-substring-match (`should not match invitations by substring`).
