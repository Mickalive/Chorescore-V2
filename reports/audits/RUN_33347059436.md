## Findings

### MustFix

1. **"Fait par" default = assignee, not the validating member** — `src/features/household/TodoScreen.tsx` (`startCompletion`, lines 145-153): `const defaultPerformer = todo.assigneeMemberId ? [todo.assigneeMemberId] : currentUser ? ...`. MAIN_PROMPT: "Fait par par défaut = membre qui valide, mais modifiable"; task acceptance: "Fait par (default=validator, modifiable)". A user who taps "Valider" without changing the field credits the assignee instead of themselves. Fix: default to the current user's member id (validator), modifiable; fall back to the assignee only if the validator is not a member. Add a test asserting the default.

2. **Reminder capability missing** — the criterion outcome requires "notes, deadline/reminder et calendrier via port", the ROADMAP lists "deadline, reminder, calendrier via port", MAIN_PROMPT says a TodoItem is "accompagnée de notes et d'un rappel", and the task acceptance requires "set deadline/reminder". `TodoItem` has no reminder field, `createTodo` accepts none, the create form has no reminder input, and `NotificationGateway`/`CalendarGateway` are never invoked by the todo flow. Fix: add `reminderAt?: string | null` to TodoItem, accept it in `createTodo`, expose it in the create form, schedule via the NotificationGateway port when available (honest adapter), and wire CalendarGateway when a real integration is configured.

3. **"Découvrir Premium" button is a no-op** — `src/features/household/TodoScreen.tsx` lines 424-429: `<Button title="Découvrir Premium" ... onPress={() => {}} />`. QG-1: "aucun bouton visible sans comportement réel ou état explicitement indisponible". The contextual upsell has no real destination. Fix: wire it to a real Premium/offers surface (household Options subscription section or a dedicated offers screen with the canonical grid) or replace it with an explicitly non-interactive informational element; align the root "Premium" button (`app/index.tsx`) and Score "Découvrir Premium" CTA for coherence.

### Non-blocking (mustFix: false)

4. **completeTodo not atomic** — `src/application/use-cases/ChoreScoreApp.ts`: the todo is marked completed before the entry is created; a failure between the two writes leaves the todo completed with no entry and the idempotency guard blocks retry. Fix: create the entry first, then mark the todo completed (or wrap in a transaction); on entry failure leave the todo open.

5. **Repository reach-in + field-name drift** — `handleDelete` calls `app.repositories.todos.delete` directly (bypassing the app layer), and the entity names (`title`/`assigneeMemberId`/`dueAt`) differ from the task acceptance list (`label`/`assignedMemberId`/`deadline`). Functionally equivalent; add a `deleteTodo` use-case and align/document the naming for traceability.

## Conclusion
The core V2-04 conversion flow is real and well-tested: Premium creation, atomic single CompletedEntry conversion, immediate Score/history propagation, Free gating with a visible tab, and downgrade-safe persistence all work, with no regression on V2-00..V2-03. Trusted verification passed (exit 0). However, three mustFix findings remain: the completion mini-form defaults "Fait par" to the assignee instead of the validating member (constitution + task acceptance), the reminder capability required by the criterion outcome is absent, and the Free-mode "Découvrir Premium" button is a dead control (QG-1). **Decision: repair.**
