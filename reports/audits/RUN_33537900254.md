## Root cause of the trusted release failure

The trusted verification for the previous candidate exited with code **1**. The authoritative
log (`reports/audits/TRUSTED_33537900254.md`) shows that `npm run check` passed (608 tests), but
the gate then failed at the `expo install --check` step, which reported:

```
The following packages should be updated for best compatibility with the installed expo version:
  expo@57.0.18 - expected version: ~57.0.19
  expo-constants@57.0.16 - expected version: ~57.0.17
  expo-font@57.0.2 - expected version: ~57.0.3
  expo-linking@57.0.8 - expected version: ~57.0.9
  expo-router@57.0.17 - expected version: ~57.0.18
  expo-sharing@57.0.16 - expected version: ~57.0.17
  @expo/metro-runtime@57.0.14 - expected version: ~57.0.15
Your project may not work correctly until you install the expected versions of the packages.
Found outdated dependencies
```

`expo install --check` returns a nonzero exit code when it finds outdated dependencies, which
caused the trusted verification to exit 1. This is the concrete release blocker.

Aligned every Expo SDK 57 package in `package.json`/`package-lock.json` to the exact versions
expected by `expo install --check`, and regenerated the lockfile:

- `expo`: `~57.0.4` → `~57.0.19`
