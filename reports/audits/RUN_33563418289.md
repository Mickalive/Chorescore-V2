## Root cause of the release failure (confirmed)

The release job's emulator `script:` block (`.github/workflows/chorescore-v2-factory.yml`) is:

```yaml
script: |
  package="${{ steps.contract.outputs.package }}"
  echo "Using validated Android package: $package"
  bash "$GITHUB_WORKSPACE/.github/scripts/smoke-android-apk.sh" "${{ steps.build.outputs.apk }}" "$package" "$RUNNER_TEMP/v2-smoke"
  ...
```

The `android-emulator-runner` action executes **each line as a separate `sh -c` process**, so the
`package` variable set on line 1 is gone by line 3. The smoke script receives an empty `$2` and
aborts on `${2:?package}`. The E2E line (`CHORESCORE_E2E_PACKAGE="$package"`) would also receive
an empty value, but `scripts/e2e-android.js` already handles that via its `app.json` fallback —
the smoke script is the fatal step.

## Findings

### MustFix — release blocker not fixed

- **path**: `.github/workflows/chorescore-v2-factory.yml` (release job, emulator script block) and `.github/scripts/smoke-android-apk.sh`
- **problem**: The V2-07 release blocker from Actions run 33552750352 is not fixed. The `android-emulator-runner` action executes each line of the `script:` input as a separate `sh -c` process, so the shell variable `package` set on line 1 does not persist to line 3, which invokes the smoke script with `$package` as its second argument. The smoke script receives an empty package and aborts with `smoke-android-apk.sh: line 3: 2: package` (exit 1), failing the release job before the Android golden path E2E can run. The candidate contains no fix: the workflow and the smoke script are byte-identical to the pristine accepted tree, so the next trusted release attempt will fail identically.
- **evidence**: `release-log.txt` lines 2144-2148 (run 33552750352, 2026-09-01T21:51:46): `[command]/usr/bin/sh -c echo "Using validated Android package: $package"` → `Using validated Android package: ` (empty) → `smoke-android-apk.sh: line 3: 2: package` → `##[error]The process '/usr/bin/sh' failed with exit code 1`. Action source at rev `a421e43855164a8197daf9d8d40fe71c6996bb0d`: `lib/script-parser.js` splits the script by newlines; `lib/main.js` runs each line via `exec.exec('sh', ['-c', line])`. Local reproduction: `sh -c 'package="com.chorescore.v2"'` followed by `sh -c 'echo "Using validated Android package: $package"'` prints an empty value. Candidate metadata: `changedFiles=1` (release-log.txt only); workflow/smoke/e2e/app.json/package.json identical to pristine.
- **mustFix**: true
- **requiredFix**: Make each line of the emulator script block self-contained: pass `${{ steps.contract.outputs.package }}` directly to `.github/scripts/smoke-android-apk.sh` and to `CHORESCORE_E2E_PACKAGE` instead of relying on the `$package` shell variable (which does not persist across the action's line-by-line `sh -c` execution); alternatively make `.github/scripts/smoke-android-apk.sh` fall back to the package from `app.json` when `$2` is empty, mirroring `scripts/e2e-android.js` `configuredAndroidPackage()`. Both fixes are in the protected `.github/**` surface: the repair must be applied by the trusted shell, or the builder scope must be explicitly extended to the release script for this repair.
- **verification**: Re-run the trusted release job (equivalent of run 33552750352): the smoke script must install and launch the release APK with the validated package `com.chorescore.v2`, and the Android golden path E2E must pass (`result.json` status=pass).
