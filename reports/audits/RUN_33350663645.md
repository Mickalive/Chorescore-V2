## What was verified (the 3 mustFix are fixed)

### MF-1 — 'Fait par' defaults to the validating member
`src/features/household/TodoScreen.tsx` `startCompletion` now resolves the current user's member id and defaults `completePerformedBy` to it (the validator), falling back to the assignee only when the validator is not a member of the household. The completion form's `Fait par` remains a modifiable `MemberSelector`. Tests in `V2-04-repair.test.ts` cover: completion by the validator when the todo is assigned to someone else, completion by the assignee when assignee == validator, modifiability to any member, and fallback to assignee when the validator is not a member. **Fixed.**

### MF-2 — Reminder capability
`TodoItem` now has `reminderAt: string | null`; `createTodo` accepts and persists it; the create form exposes a reminder input; and `createTodo` schedules a notification via the `NotificationGateway` port only when `isAvailable()` is true (the `LocalNotificationAdapter` returns false and throws, so no fake notification is scheduled in the real app — honest). Tests cover persistence/round-trip, null default, scheduling when available, no scheduling when unavailable, multi-todo persistence, and downgrade preservation. **Fixed.**

### MF-3 — 'Découvrir Premium' wired to a real surface
A real `/premium` offers screen (`app/premium/index.tsx`) exists and is registered in `app/_layout.tsx`. The root `Premium` button (`app/index.tsx`), the AddTask and Score `ArchiveMessage` CTAs, the Score year/all-time `Découvrir Premium` CTA, and the TodoScreen upsell `Découvrir Premium` all `router.push('/premium')`. The screen shows the canonical pricing grid (Trial 30 days, Free, Standard 2,99 €/7 members, Pro 5,99 €/8 members) using the app design system. **Fixed.**

### Regression
V2-00..V2-03 suites remain green; the core V2-04 conversion flow (create/complete/Score propagation, Free upsell, downgrade persistence) is preserved. No governance/constitution/roadmap/task file modified. No V1 carry-over, no fake integrations, no domain/provider coupling.

## Findings

### MustFix

1. **Premium offers screen purchase CTAs are fake** — `app/premium/index.tsx`: the buttons `Commencer l'essai` (lines 56-61), `Choisir Standard` (105-110) and `Choisir Pro` (129-134) are styled as active primary/secondary purchase actions but each only calls `router.back()` and performs no real action, and none is marked unavailable/disabled. QG-1: "aucun bouton visible sans comportement réel ou état explicitement indisponible". Constitution: "Aucun paiement factice ne doit être présenté comme réel dans une RC locale." This is a fake payment presented as real, introduced by this repair's new surface. Fix: disable these CTAs with an explicit "indisponible" state (billing not configured) or wire them to a real action (e.g., `startTrial` via `EntitlementGateway` in demo/test mode).

### Non-blocking (mustFix: false)

2. **completeTodo not atomic** — `src/application/use-cases/ChoreScoreApp.ts`: the todo is marked completed before the entry is created; a failure between the two writes leaves the todo completed with no entry and the idempotency guard blocks retry. Optional per the task; not blocking.

3. **Repository reach-in for deletion** — `handleDelete` calls `app.repositories.todos.delete` directly, bypassing the app layer. Optional per the task; not blocking.

4. **Weak MF-3 tests** — the MF-3 tests in `V2-04-repair.test.ts` mostly assert `expect(true).toBe(true)` and entitlement state rather than actual navigation. The navigation wiring is correct in the UI code (verified directly), but the tests do not exercise it. Not blocking.

## Conclusion
The three mustFix findings from RUN 33347059436 are genuinely fixed: the completion mini-form defaults 'Fait par' to the validating member, TodoItem now supports reminders with honest NotificationGateway scheduling, and all 'Découvrir Premium' buttons navigate to a real offers surface. Trusted verification passed (exit 0, 298 tests, Android build successful). However, the new premium offers screen introduces a mustFix: its purchase CTAs are visible, active-looking, and do nothing (fake payment per QG-1 and the constitution). **Decision: repair.**
