## Audit Findings (Must-Fix)

### MF-1 — Non-member permission grant
**Path:** `src/application/use-cases/ChoreScoreApp.ts`
**Problem:** `getMemberPermissionLevel` returns `'MEMBER'` for a user with no membership in the household. MEMBER-level permissions include `canCreateEntry: true`, granting strangers write access to any household.
**Required fix:** Return a no-access result (or throw) for non-members. Update test to assert correct behavior.

### MF-2 — Conflict log tenant isolation violation
**Path:** `src/infrastructure/local/LocalSyncAdapter.ts`
**Problem:** `getConflictLog(_householdId)` ignores the `householdId` parameter and returns ALL conflicts across ALL households. `logConflict` derives a bogus householdId from `entityId.split('-')[0]`.
**Required fix:** Add explicit `householdId` parameter to `logConflict`. Make `getConflictLog(householdId)` return only that household's conflicts. Add two-household isolation test.

### MF-3 — getPendingInvitations userId/email mismatch
**Path:** `src/application/use-cases/ChoreScoreApp.ts` + `src/infrastructure/local/LocalInvitationAdapter.ts`
**Problem:** App-level `getPendingInvitations(userId)` passes userId to adapter which matches against `invitedEmail` using substring `includes` — functionally broken and privacy-leaky.
**Required fix:** Resolve userId to email in app layer via `repositories.users.getById()`. Replace substring `includes` with exact email matching in adapter.
