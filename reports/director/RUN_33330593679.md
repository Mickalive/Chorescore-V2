## Remaining Finding

**F4 (mustFix):** In `LocalEntitlementAdapter.getAccountEntitlement`, demo-premium mode consults `AccountRepository.ownedFreeHouseholdId` and returns `canCreateFreeHousehold: ownedFreeHouseholdId === null`. After creating one household, this returns `false`, which disables the root screen's "Create household" button. But `createHousehold` in `ChoreScoreApp.ts` has a demo-premium bypass (line 188–198) that always allows creation.

**Required fix:** In demo-premium mode, `getAccountEntitlement` must always return `canCreateFreeHousehold: true` (consistent with `createHousehold`'s bypass), while still reporting accurate `ownedFreeHouseholdId` from AccountRepository. In demo-free mode, the one-free-household rule remains enforced.
